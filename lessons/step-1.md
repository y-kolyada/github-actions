## Предикаты

1. **Две страницы написаны, остальные шестьдесят шесть не тронуты.** В `ru/index.html` и `ru/01.html` не осталось строки «Текст этого раздела ещё не написан.» и не осталось плашки-заглушки; `data-words` каждой из двух не меньше **800**. Пятнадцать названий разделов в навигации остаются «Раздел 1 … Раздел 15», словарь остаётся скелетом, `en/ uk/ de/` не тронуты. **Чем проверяется:** машиной - `grep -c 'ещё не написан' ru/index.html ru/01.html` даёт ноль; `git diff --name-only` называет только `ru/index.html`, `ru/01.html`, `site.conf`, `sitemap.xml`, перестроенные `assets/search-*.json` и файлы `lessons/`.

2. **Каждое утверждение этих двух страниц исполнено до публикации.** Ни один факт о GitHub Actions не попадает на страницу, пока он не напечатан терминалом этой сессии. Проверки, которые это держат, - `tools/check-claims.sh` (факты) и `tools/check-examples.sh` (примеры со страниц), обе возвращают 0, и в первой есть отдельное утверждение на каждый проверяемый факт двух страниц, а не одно общее. **Чем проверяется:** машиной - `./tools/check-claims.sh && ./tools/check-examples.sh` возвращает 0; число строк-утверждений в выводе не меньше числа фактов, вынесенных на страницы. Глазами - Архитектор сверяет список утверждений с текстом страниц.

3. **Сайт остаётся собранным, и поиск находит слово темы.** В `site.conf` стоит `search = workflow`, слово находится поиском по собранному индексу, `./check.sh` отвечает одним словом **ЗЕЛЁНОЕ**. **Чем проверяется:** машиной - `python3 tools/build-meta.py`, `python3 tools/build-search.py`, затем `./check.sh` с кодом 0.

Здесь нужно слово: **два файла `tools/check-claims.sh` и `tools/check-examples.sh` этот сайт пишет у себя** (так сделано в `courses/bash`) **или они приходят из ростка заготовками?**

Вместе с этим - чем исполняются утверждения. Что есть в этой сессии: `gh` 2.100.0, авторизован как `y-kolyada`; `docker` 29.8.1; `node` 24; `python3` 3.14. Чего нет: `act`, `actionlint`, модуля `PyYAML`. Отсюда три возможных механизма, по убыванию честности:

| Механизм | Что доказывает | Цена |
| :-- | :-- | :-- |
| `gh api` только на чтение | как GitHub на самом деле отвечает: схема `workflow_run`, поля контекста, список триггеров | нужна сеть; ничего не ставится |

Ставить что-либо в систему исполнитель не начинает без слова Архитектора.

## Поправка к предикатам · база диффа и пол по объёму

Форма взята из `courses/terraform/lessons/step-1.md`: обе проверки дешёвые и ловят реальное.

**1. Дифф мерится от названного коммита.** База - `dd6af23`: состояние, в котором принят план пятнадцати разделов и `./check.sh` печатает ЗЕЛЁНОЕ, восемь ДА из восьми.

```
git diff --name-only dd6af23
```

Вывод обязан содержать только: `ru/index.html`, `ru/01.html`, сгенерированные блоки (`sitemap.xml`, `assets/search-*.js`), `tools/claims.tsv`, `site.conf` и файлы `lessons/`. Любое другое имя в этом списке - работа не принята. Это превращает «ничего лишнего не тронул» из обещания в команду.

**2. Скелетные фразы запрещены машиной, и у объёма есть пол.**

```
grep -c 'Текст этого раздела ещё не написан' ru/index.html ru/01.html   # обязан дать 0
grep -o 'data-words="[0-9]*"' ru/index.html ru/01.html                  # не меньше 600 каждая
```

Пол - **600 слов** на страницу. Где в предикате 1 выше стоит другое число, оно остаётся ориентиром, а 600 - то, ниже чего машина не пропускает. Без этой пары «страница написана» проверяется глазами, а значит мнением.

**3. Правило утверждений, дословно.**

> Не вписал команду в `tools/claims.tsv` - утверждения на странице нет.

Манифест - строка «утверждение TAB ожидаемый вывод TAB команда», и проверка её запускает. Пустой манифест зелёный, и это не лазейка: пустой манифест означает, что сайт об инструменте пока ничего не утверждает. Первое слово про `workflow` на странице - первая строка в манифесте.

**Пол, цель и соблазн финиша.** Пол 600 слов - это то, ниже чего машина не пропускает, а не норма. Норма - эталон серии: `courses/bash/ru/index.html` 1128 слов, `ru/01.html` 1117. Предикат 1 выше просит 800 и остаётся как есть; расхождение числа в предикате, пола и нормы разрешается так:

> **Если время кончается, сдаётся одна полная страница, а не две по шестьсот слов.** Скелет не врёт: он прямо говорит «текст этого раздела ещё не написан». Полупустая страница врёт, потому что выглядит написанной. Недописанную страницу возвращают в скелет (`git restore`) и пишут честную строку в `lessons/record-1.md`, а не дотягивают до пола.

Пол ловит страницу, которую выдали за написанную. Он не разрешает писать до пола.
