## Задание 1 · первые две страницы на русском

**Исполнитель:** Claude Code. **Сайт:** `devops-github-actions`, репозиторий `github-actions`,
плашка `GitHub Actions`, ключ хранилища `gha`, слово поиска `workflow`.

**Состояние на входе.** Сайт заштампован из ростка: 68 страниц, русские - скелеты, три языка -
заглушки. Шесть проверок из восьми зелёные. Две красные по дефекту ростка, он записан в
`lessons/notes-1.md` и правится не здесь.

**Хочу:** две русские страницы настоящего текста вместо скелетов - посадочную `ru/index.html`
и первую тему `ru/01.html` - и каждое их утверждение о GitHub Actions, исполненное в
терминале до публикации, а не пересказанное из документации.

**Посадочная держит читателя,** а не перечисляет оглавление прозой: что это за сайт, кому он
нужен, с чем читатель уходит. **Первая тема даёт механизмы,** на которые обопрутся остальные
четырнадцать: что такое workflow, что его запускает, где он выполняется, что видит из
репозитория. Ориентир по объёму - эталонный сайт серии: `ru/index.html` 1128 слов,
`ru/01.html` 1117.

## Предикаты

1. **Две страницы написаны, остальные шестьдесят шесть не тронуты.** В `ru/index.html` и
   `ru/01.html` не осталось строки «Текст этого раздела ещё не написан.» и не осталось
   плашки-заглушки; `data-words` каждой из двух не меньше **800**. Пятнадцать названий
   разделов в навигации остаются «Раздел 1 … Раздел 15», словарь остаётся скелетом,
   `en/ uk/ de/` не тронуты.
   **Чем проверяется:** машиной - `grep -c 'ещё не написан' ru/index.html ru/01.html` даёт
   ноль; `git diff --name-only` называет только `ru/index.html`, `ru/01.html`, `site.conf`,
   `sitemap.xml`, перестроенные `assets/search-*.json` и файлы `lessons/`.

2. **Каждое утверждение этих двух страниц исполнено до публикации.** Ни один факт о GitHub
   Actions не попадает на страницу, пока он не напечатан терминалом этой сессии. Проверки,
   которые это держат, - `tools/check-claims.sh` (факты) и `tools/check-examples.sh`
   (примеры со страниц), обе возвращают 0, и в первой есть отдельное утверждение на каждый
   проверяемый факт двух страниц, а не одно общее.
   **Чем проверяется:** машиной - `./tools/check-claims.sh && ./tools/check-examples.sh`
   возвращает 0; число строк-утверждений в выводе не меньше числа фактов, вынесенных на
   страницы. Глазами - Архитектор сверяет список утверждений с текстом страниц.

3. **Сайт остаётся собранным, и поиск находит слово темы.** В `site.conf` стоит
   `search = workflow`, слово находится поиском по собранному индексу, `./check.sh` отвечает
   одним словом **ЗЕЛЁНОЕ**.
   **Чем проверяется:** машиной - `python3 tools/build-meta.py`, `python3 tools/build-search.py`,
   затем `./check.sh` с кодом 0.

## Границы

**В задании нет:**

- английского, украинского и немецкого - они идут после приёмки русского оригинала;
- пятнадцати названий разделов и словаря: план разделов утверждает Архитектор отдельно,
  придумывать имена попутно - не решение исполнителя;
- страниц `ru/02.html … ru/15.html`, банков вопросов и `ru/glossary.html`;
- правки `assets/` - ни одной строки, ни при каких обстоятельствах (AGENTS.md §1);
- `git push` и мержа в `prod` - исполнитель останавливается на локальном коммите.

**Один вопрос к Архитектору, без ответа на который предикат 2 не закрыть.** AGENTS.md §5.7
говорит, что проверка примеров пишется под каждый сайт и живёт в `tools/`; скил запуска
говорит, что сайт не правит `tools/`. Для первого сайта серии эти два правила не
противоречили друг другу, потому что проверку писал эталон. Здесь нужно слово: **два файла
`tools/check-claims.sh` и `tools/check-examples.sh` этот сайт пишет у себя** (так сделано в
`courses/bash`) **или они приходят из ростка заготовками?**

Вместе с этим - чем исполняются утверждения. Что есть в этой сессии: `gh` 2.100.0,
авторизован как `y-kolyada`; `docker` 29.8.1; `node` 24; `python3` 3.14. Чего нет: `act`,
`actionlint`, модуля `PyYAML`. Отсюда три возможных механизма, по убыванию честности:

| Механизм | Что доказывает | Цена |
| :-- | :-- | :-- |
| `gh api` только на чтение | как GitHub на самом деле отвечает: схема `workflow_run`, поля контекста, список триггеров | нужна сеть; ничего не ставится |
| `act` + `docker` | что workflow со страницы действительно выполняется | ставится `act` |
| разбор YAML (`PyYAML`) | ловушки синтаксиса: `on:` как булево `True` в YAML 1.1, скаляры, отступы | ставится `PyYAML` |

Ставить что-либо в систему исполнитель не начинает без слова Архитектора.

**В `lessons/backlog.md` уходит:** план пятнадцати разделов, словарь, три перевода, выбор
механизма исполнения утверждений, если он откладывается.

## План пятнадцати разделов · GitHub Actions

Порядок: 01 отвечает «что происходит, когда я толкнул коммит», дальше каждая тема стоит на
механизме, разобранном раньше. Разбор - 01-09, примеры - 10-12, банки по 50 вопросов - 13-15.

| № | Название | О чём |
| :-- | :-- | :-- |
| 01 | Что такое workflow и где он выполняется | Файл в `.github/workflows`, событие, job, step, runner: путь от толчка коммита до галочки. |
| 02 | События: что запускает workflow | `push`, `pull_request`, `schedule`, `workflow_dispatch`, фильтры по ветвям, тегам, путям. |
| 03 | Контексты и выражения | `${{ }}`, контексты `github`, `env`, `steps`, `needs`, `inputs`; `if` на шаге и на job. |
| 04 | Job'ы, зависимости, матрица | `needs` как граф, `strategy.matrix`, `fail-fast`, `concurrency`: что идёт параллельно. |
| 05 | Шаги: `run` против `uses` | Своя команда или чужое действие, `actions/checkout`, пин на тег и на sha как вопрос доверия. |
| 06 | Рабочая машина и окружение | Образ runner'а, рабочая папка, `env`, `GITHUB_ENV`, `GITHUB_OUTPUT`, `GITHUB_STEP_SUMMARY`. |
| 07 | Секреты и права | `secrets`, `GITHUB_TOKEN` и его `permissions`, окружения с ревью, OIDC вместо долгих ключей. |
| 08 | Артефакты и кеш | `upload-artifact`, `download-artifact`, `actions/cache`, промах ключа, срок жизни. |
| 09 | Почему workflow упал | Чтение логов, повтор одного job, `ACTIONS_STEP_DEBUG`, ошибки отступа и кавычек в YAML. |
| 10 | Пример: проверка кода на каждый push | Линт и тесты на матрице версий, кеш зависимостей, условие на черновой pull request. |
| 11 | Пример: сборка и публикация по тегу | Релиз на тег, артефакт сборки, публикация страницы, права по job'ам. |
| 12 | Пример: переиспользуемый workflow | `workflow_call`, входы и выходы, composite action, граница «своего» и «общего». |
| 13 | Банк: основы и синтаксис | 50 вопросов на 01-02, 05-06: структура файла, события, шаги, окружение. |
| 14 | Банк: контексты, права, данные | 50 вопросов на 03-04, 07-08: выражения, граф job'ов, секреты, кеш. |
| 15 | Банк: разбор сбоев | 50 вопросов на 09 и примеры: по симптому назвать причину. |
| - | Словарь | Термины 01-09: workflow, job, step, runner, action, контекст, артефакт, кеш, OIDC. |

**План не трогает разметку.** Названия в страницах и навигаторе остаются «Раздел N» до
следующей поставки: навигатор собирает `tools/build-nav.py`, и правятся страницы, а не
инструмент. Первая строка следующего задания - перенести эти названия в разметку.
